# Прозрачное UDP-реле

Клиент подключается к адресу реле. Реле пересылает зашифрованные датаграммы в существующий туннель на сервере выхода. Туннель расшифровывает трафик и использует свой обычный выход, напрямую или через WARP. Одна запись реле обслуживает несколько клиентов одного туннеля.

Первая версия поддерживает Ubuntu 24.04 LTS и 26.04 LTS на хостах реле с архитектурой x86_64. CI запускает smoke-тест UDP-реле на обеих версиях. Установку и удаление дополнительно проверили в VM с Ubuntu 24.04.5 LTS x86_64. Поддержка реле на CentOS Stream и RHEL отложена. Для сервера выхода действует прежний список поддерживаемых платформ AWG-Forge.

## Настройка

1. В панели открой **Туннели**, выбери туннель и перейди на вкладку **UDP-реле**. Нажми **Добавить реле** и введи его публичный адрес. Панель подставляет порт и настроенный адрес туннеля. Можно указать другое DNS-имя или IPv4-адрес, доступный с реле. Порт назначения берётся из настроек туннеля. Если оставить название пустым, панель использует публичный адрес.
2. Скопируй команду установки и выполни её на промежуточном сервере. Команда скачивает установщик конкретного релиза и запускает `install.sh relay`. Установщик предложит установить Docker Engine, Compose v2 и недостающие утилиты. Если Docker уже работает, установщик использует его. Включи `net.ipv4.ip_forward` на хосте реле. Разреши входящий UDP на порту реле в файрволе провайдера и доступ от реле к UDP-порту туннеля.
3. При создании или редактировании клиента выбери реле в поле **Способ подключения**. Пункт **Напрямую** использует адрес туннеля. Экспортируй конфигурацию и импортируй её на устройстве. После смены адреса или порта выдай затронутым клиентам новые конфиги.

Для домена реле используй IPv4-запись. Установщик выбирает локальный адрес и интерфейс из маршрута до сервера выхода. Входящий UDP должен приходить на этот адрес и интерфейс. Для фиксированного IPv4 при смене маршрута повторно выполни команду установки. Если задано DNS-имя, реле разрешает его в IPv4 при запуске и обновляет результат каждую минуту. Реле сохраняет текущий адрес, пока он есть в ответе DNS, и оставляет правила в силе при временном сбое DNS.

## Обслуживание

Команда установки из панели скачивает `install.sh` в текущий каталог на хосте реле под именем `awg-forge-install.sh`. Используй этот файл или скачай скрипт из `master` для команд обслуживания.

```bash
curl -fsSL https://raw.githubusercontent.com/astronaut808/awg-forge/master/install.sh -o awg-forge-install.sh
```

Чтобы узнать ID реле, открой **Туннели**, выбери нужный туннель и перейди на вкладку **UDP-реле**. Рядом с нужным реле нажми **Установка**. Скопируй значение после `--id` из поля **Команда установки** или **Команда удаления** и подставь его вместо `0123456789abcdef` в примерах ниже.

```bash
sudo bash ./awg-forge-install.sh relay status --id 0123456789abcdef
```

Чтобы удалить реле после переключения его клиентов, выполни команду на хосте реле.

```bash
sudo bash ./awg-forge-install.sh relay remove --id 0123456789abcdef
```

Контейнер запускается при старте Docker и восстанавливает свои правила. `status` проверяет контейнер и правила на хосте. Панель проверяет публичный адрес при запуске и повторяет проверку примерно раз в минуту. Сервер выхода выполняет AWG-рукопожатие через реле с помощью временного пира без маршрутов туннеля. В панели видны результат и время последней успешной проверки. Эта проверка подтверждает обмен в обе стороны между серверами. Чтобы проверить доступ из сети клиента или выход в интернет, подключись из этой сети и проверь трафик.

После изменения настроек реле выполни новую команду установки на промежуточном сервере. Изменение адреса назначения требует повторной установки, даже если клиентские конфиги остались актуальными. Перед удалением реле переключи его клиентов, удали контейнер командой `relay remove` и удали запись в панели. Перед сменой порта или удалением туннеля сними все его реле.

Реле использует отдельный Compose-проект. Контейнер управляет своими правилами iptables-nft, а пакеты пересылает ядро Linux. Выдели реле свободный UDP-порт. Проверь, что действующие правила на хосте и цепочки сторонних файрволов пропускают нужный трафик.

Для ручного отката на v0.20.0 останови сервер выхода и сохрани отдельную копию его каталога данных v4. Восстанови резервную копию v3, сделанную до обновления, затем запусти v0.20.0. Запуск v0.20.0 с каталогом данных v4 может удалить настройки реле и привязки клиентов. Можно также установить v0.20.0 с чистым каталогом данных и пересоздать туннели и клиентов. Повторно импортируй конфиги для прямого подключения и удали реле с его хоста, если оно больше не нужно. См. [резервное копирование и восстановление](diagnostics.md#encrypted-backup--restore).

Если установка прервалась, запусти команду повторно. Установщик проверит контейнер и сохранит новую конфигурацию либо восстановит предыдущую. Правила реле добавляются в конец `FORWARD`, поэтому правила файрвола, которые уже находятся в цепочке, срабатывают первыми.

Реле сохраняет рабочие IPv4-адреса и UDP-порты на хосте перед установкой DNAT. При удалении эта запись позволяет очистить соответствующие записи conntrack даже после перезагрузки файрвола. Для старых установок без такой записи параметры можно восстановить из сохранившихся правил реле.
