# Разработка

Используйте версию Go из `go.mod` и версии Node.js и npm из `package.json`.
Версии инструментов CI указаны в файлах рабочих процессов и в Makefile.

## Сборка и тесты

```bash
npm ci
npx --no-install playwright install chromium
npm run ui:build
make ci
git diff --check
```

В Linux добавьте `--with-deps` при установке Chromium, если не хватает системных
библиотек. `make ci` запускает тесты Go, shell-скриптов и интерфейса, линтеры и
проверку контракта OpenAPI. Для отдельной проверки установки, обновления и
удаления запустите `make test-shell`.

Исходники интерфейса находятся в `web/`. После изменений запустите
`npm run ui:build`, чтобы обновить файлы, встроенные в бинарник Go.

## Локальный запуск интерфейса

```bash
config_dir="$(mktemp -d "${TMPDIR:-/tmp}/awg-forge-dev.XXXXXX")" &&
CONFIG_DIR="$config_dir" \
WEBUI_HOST=127.0.0.1 \
WEBUI_PORT=51821 \
WEBUI_USERNAME=admin \
PASSWORD=test \
APPLY_CONFIG=false \
go run ./cmd/awg-forge serve
```

Откройте <http://127.0.0.1:51821> и войдите с логином `admin` и паролем `test`.
Данные сохраняются во временный каталог, а `APPLY_CONFIG=false` отключает
применение настроек туннелей на хосте.

Для разработки интерфейса запустите `npm run ui:dev` и откройте
<http://127.0.0.1:51923/static/>. Сервер разработки по умолчанию обращается к
локальному серверу на `127.0.0.1:51821`. Если адрес отличается, задайте
`AWG_UI_BACKEND`. Если порты браузерных тестов заняты, задайте `UI_TEST_PORT`.

## Проверки перед релизом

```bash
make security
make docker-build
make docker-smoke IMAGE=awg-forge:local
make docker-runtime-smoke IMAGE=awg-forge:local
```

Для быстрой локальной проверки можно использовать `make security-fast`. Для
проверки передачи зашифрованного IPv4-трафика по всем поддерживаемым профилям
нужен Linux Docker Engine с `/dev/net/tun`. Тест использует изолированную сеть
Docker. Обновление, откат и работу нативных VPN-клиентов проверяйте отдельно
на тестовой установке.

Подготовь проверенный кандидат в релизной ветке и открой PR в `master`.
После проверки развёртывания оформи датированную секцию changelog и версию
OpenAPI. Создавай подписанный тег версии после попадания релизного коммита
в `master`.

CI тега проверяет принадлежность коммита истории `master` и заметки релиза,
собирает поддерживаемый образ `linux/amd64`, запускает оба Docker smoke-теста
и Trivy, затем передаёт и публикует проверенный образ. Публикация GitHub
Release зависит от успешной публикации образа.
